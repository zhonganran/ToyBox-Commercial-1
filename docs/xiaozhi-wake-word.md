# 小智后台语音唤醒

## 行为

- 默认开启，默认唤醒词为“小智”。
- 可在“设置 → 小智对话 → 服务接入 → 后台语音唤醒”修改为任意 2～16 个字或字符的自定义名称。
- 命中唤醒词后播放短提示音，释放识别麦克风，再启动原有小智对话链路。
- 唤醒启动的会话固定使用服务端 `auto` VAD：提示音后直接说话，不需要点“结束说话”。
- 小智回答播放完成后会自动继续收音，可以连续追问；18 秒没有新的语音时结束本次对话，恢复等待唤醒词。
- 识别完成后 45 秒仍没有服务器回答时，会播放失败提示音、释放音频资源并恢复后台唤醒。
- 服务器已开始回答但 90 秒仍没有结束事件时，同样会自动收口，避免永久卡在“正在回答”。
- 对话结束后可短暂复用 WebSocket 降低下一次唤醒延迟；空闲 120 秒后自动断开。
- 对话结束后自动恢复唤醒监听，不要求停留在小智页面。
- 应用和用户运行环境恢复后会尝试重新启动前台唤醒服务。

## 识别引擎

优先使用 Android 12 的系统离线语音识别；车机没有离线中文引擎时，回退到系统语音识别服务。唤醒词匹配在应用本地完成，不把控制台密码、Token 或车辆数据交给识别器。

系统识别服务是否真正离线由车机 ROM 决定。设置页会显示当前引擎与运行状态，日志标签为 `XiaozhiWake`。
识别器或后台服务启动失败时使用有上限的指数退避自动重试。两字短唤醒词只接受完整命中，并在 ROM 提供置信度时过滤低置信度结果。

## 麦克风互斥

`AudioUsageCoordinator` 统一维护后台唤醒、小智对话、实时喊话和车外音效的资源所有者：

- 小智正式对话开始前，唤醒监听先停止并释放麦克风。
- 实时车外喊话开始前，唤醒监听让行；喊话停止后恢复。
- 小智回答播放期间不重新开启监听，避免把小智自己的声音当成唤醒词。
- 实时喊话与小智对话互相抢占时，后发的显式操作接管麦克风。
- 新功能会等待原有 `AudioRecord` 和车外路由确认释放，不再仅依赖固定延时。
- 小智对话占用车内回答通道时，新的车外音效会跳过，防止回答被路由到车外。

小智会话的 UI、后台服务、WebSocket、录音和播放回调都进入同一个串行命令队列，避免“已停止后又重新录音”等竞争。

唤醒监听不建立小智 WebSocket，也不运行 Opus 编解码。只有真正唤醒后才启动云端会话。

## 真车验证

需要在目标 DiLink 车机验证：

1. ROM 是否提供中文 `RecognitionService`。
2. 离线中文识别是否已安装；没有时系统回退是否需要联网。
3. 车辆休眠、通电和应用自启动后的前台麦克风权限。
4. 驾驶噪声下默认唤醒词“小智”和自定义短名称的误唤醒率。
5. 实时喊话、小智对话和原车语音助手之间的麦克风抢占情况。
